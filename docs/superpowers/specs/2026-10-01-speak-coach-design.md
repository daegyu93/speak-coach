# speak-coach 설계 문서

- 작성일: 2026-10-01
- 상태: 설계 승인, 구현 계획 작성 전

## 1. 목적

2027년 3월 NVIDIA GTC 부스에서 직접 개발한 센서를 영어로 설명하기 위해, 그 전까지 **영어 말하기와 듣기를 매일 연습**하는 개인용 AI 회화 웹앱을 만든다.

- 사용자: 개발자 본인 1명 (영어 레벨 CEFR A2 정도, 회화 수업 경험 없음)
- 판매는 나중에 검토한다. 첫 버전은 판매 기능을 넣지 않는다.

### 성공 기준

1. 안드로이드 크롬에서 앱을 열고 → 상황을 고르고 → 음성으로 대화하고 → 교정을 받는 흐름이 막힘없이 끝까지 돈다.
2. 교정은 텍스트 연습 세션과 같은 형식(틀린 문장 → 자연스러운 표현 → 한국어 포인트)으로 나온다.
3. 운영 비용이 0원이다 (Gemini 무료 티어, 무료 호스팅).

## 2. 결정 사항

| 항목 | 결정 | 이유 |
|---|---|---|
| 형태 | 웹앱(PWA). 안드로이드 앱은 나중에 Capacitor로 변환 | 빌드·서명·스토어 배포가 필요 없다 |
| AI 모델 | Google Gemini API (Flash 계열, 무료 티어) | Claude 구독과 별도로 API 비용을 내지 않는다 |
| 서버 | 없음. 정적 호스팅 + 브라우저에서 Gemini 직접 호출 | 관리·비용 0. 본인 전용이라 키 노출 위험이 없다 |
| API 키 | 앱 설정 화면에서 입력, 폰 브라우저(IndexedDB)에만 저장 | 코드와 저장소에 키를 넣지 않는다 |
| 음성 | 브라우저 내장 음성 인식(Web Speech API) + 브라우저 TTS(speechSynthesis) | 무료. 텍스트 기반이라 교정이 정확하다 |
| 호스팅 | GitHub Pages (공개 저장소 `daegyu93/speak-coach`) | 무료, HTTPS 자동 (마이크 사용에 HTTPS 필수) |
| 스택 | Vite + TypeScript + Preact, vite-plugin-pwa | 가볍고 폰에서 빨리 뜬다 |

## 3. 구조

각 모듈은 한 가지 역할만 맡고, 인터페이스로 분리해서 내부 구현을 바꿔도 다른 모듈이 영향받지 않게 한다.

```
src/
├─ speech/     음성 인식(STT), 음성 출력(TTS)
├─ ai/         Gemini 호출, 프롬프트 생성, 응답 검증
├─ scenarios/  상황 목록 데이터
├─ storage/    대화 기록, 실수 노트, 설정 (IndexedDB)
└─ ui/         화면
```

- `speech/`는 `SpeechInput`(start/stop → 텍스트), `SpeechOutput`(speak/cancel) 인터페이스를 노출한다. 나중에 녹음 파일을 Gemini로 보내는 방식이나 Gemini Live API로 교체할 수 있다.
- `ai/`는 `ChatModel` 인터페이스(턴 응답, 세션 교정)를 노출한다. 다른 모델로 교체할 수 있다.

## 4. 화면

1. **홈**: 상황 목록 + "직접 상황 입력" + 모드 선택
2. **대화**: 누르고 말하기 🎤 버튼(워키토키 방식, 떼면 전송), 텍스트 입력 칸(항상 제공), 말풍선 대화, AI 답변 자동 재생과 🔊 다시 듣기
3. **교정 결과**: 교정 표(내 문장 / 자연스러운 표현 / 한국어 포인트) + 오늘 배운 표현 + 한 줄 총평
4. **실수 노트**: 저장된 교정 목록 + 자주 틀리는 유형 TOP 3
5. **설정**: API 키, 말하기 속도, 목소리 선택

### 모드

- **대화 후 교정**: 대화 중에는 교정하지 않고, 종료하면 교정 결과 화면을 보여 준다.
- **문장마다 교정**: 매 턴마다 교정 카드를 먼저 보여 주고, 그다음 AI 답변을 재생한다.

### 상황 목록 (첫 버전)

입국심사, 호텔 체크인, 카페 주문, 식당, 우버·길 묻기, 행사장 스몰토크 + 직접 입력. GTC 부스 전문 용어 시나리오는 나중에 추가한다.

## 5. AI 동작

### 시스템 프롬프트 규칙

- 선택한 상황의 역할을 연기한다 (입국심사관, 바리스타, 행사장 참가자 등).
- 사용자 레벨(A2)에 맞춰 짧고 쉬운 문장으로 말하고, 한 번에 질문은 하나만 한다.
- 교정은 틀린 문장 → 자연스러운 표현 → 한국어 짧은 설명 순서로 한다. 문화·뉘앙스 팁은 있을 때만 넣는다.
- 뜻이 통하면 통한다고 먼저 말하고, 잘한 점은 칭찬한다.

### 응답 형식

Gemini의 JSON 스키마 출력(structured output)을 사용하고, 받은 응답은 앱에서 다시 검증한다.

```
턴 응답 (대화 후 교정 모드):   { reply }
턴 응답 (문장마다 교정 모드):  { feedback?: Correction, reply }
세션 교정:                     { corrections: Correction[], phrases: Phrase[], summary_ko }
```

```
Correction = {
  original: string,   // 사용자가 한 말
  better:   string,   // 자연스러운 표현
  point_ko: string,   // 한국어 짧은 설명
  category: Category,
  ok:       boolean   // 뜻은 통했는지
}
Phrase = { en: string, ko: string }   // 오늘 배운 표현
Category = missing_verb | tense | article | word_choice | word_order
         | expression | adj_adv | culture
```

### 실수 노트 반영

- 교정 결과(Correction)는 자동으로 실수 노트에 저장한다.
- 새 대화를 시작할 때 TOP 3 유형과 최근 예시 몇 개를 시스템 프롬프트에 넣는다. AI는 그 유형이 나오기 쉬운 질문을 자연스럽게 섞는다.

## 6. 오류 처리

| 상황 | 처리 |
|---|---|
| 마이크 권한 거부 / 음성 인식 미지원 | 안내 후 텍스트 입력으로 전환 |
| 음성이 인식되지 않음 | "잘 안 들렸어요, 다시 말해 주세요" 안내 |
| API 키 없음 / 잘못된 키 | 설정 화면으로 안내 |
| 무료 한도 초과 (HTTP 429) | 안내 + 자동 재시도 1회 |
| 네트워크 오류 | 사용자 입력은 유지하고 "다시 보내기" 버튼 제공 |
| 응답 형식 오류 | 자동 재시도 1회, 실패 시 오류 안내 |

## 7. 테스트

- **자동 테스트 (Vitest)**: 프롬프트 생성, 응답 파싱·검증, 실수 노트 저장, TOP 3 계산. AI와 음성은 mock으로 대체한다.
- **실기기 체크리스트 (안드로이드 크롬)**: 마이크 권한, 음성 인식, TTS 재생, 홈 화면 설치, 두 모드로 대화 1회씩 완주, 실수 노트 반영 확인.

## 8. 범위 밖 (나중에)

로그인, 결제, 발음 점수, 실시간 음성 대화(Gemini Live API), 녹음 파일 기반 인식, 플래시카드 퀴즈, 안드로이드 앱 변환, GTC 부스 전문 용어 시나리오, 서버리스 프록시(판매·공유 시).

## 9. 확인이 필요한 사항

- 사용자가 받은 API 키가 `AQ.`로 시작하는 형식이다. 구현할 때 Gemini API에서 동작하는지 확인한다.
- Gemini 무료 티어의 현재 모델명과 호출 한도는 구현할 때 공식 문서로 확인한다.
- 무료 티어는 대화 내용이 구글의 모델 개선에 쓰일 수 있다. 회사 기밀은 입력하지 않는다.
